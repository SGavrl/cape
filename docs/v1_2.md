# CAPE v1.2 experiment protocol

## Semantic contract

`CAPE(context, assertion)` estimates the probability that the assertion is
warranted by the supplied context, allowing ordinary background knowledge.
Topical association and unsupported plausibility are not support.

The internal supervision keeps these states distinct when labels are
available:

- **entailment:** the context warrants the assertion;
- **neutral / unsupported:** the context neither warrants nor contradicts it;
- **contradiction:** the context warrants that the assertion is false;
- **relevance:** a passage contributes evidence toward answering a question;
- **assertion strength:** possible, likely, or certain.

For v1.2, neutral NLI examples have support target `0`, with `nli_label` set to
`neutral`. The value `0.5` is reserved for a real probabilistic or aggregate
target; it is not an encoding for the neutral class. Optional auxiliary fields
are masked when absent.

## Diagnosis

The v1.1 data path maps SNLI neutral to `0.5`, while other negative examples
map both contradiction and lack of support to `0`. That asks one scalar head to
represent incompatible meanings. The easy SQuAD negatives come from unrelated
titles, and the synthetic train and test sets share surface templates. Those
choices explain why in-distribution metrics can be excellent while indirect
relevance, unsupported specialization, and varied temporal language fail.

The first-token cross-encoder remains a strong quality baseline, but
`judge_many()` repeats the full context for every assertion. Batching improves
hardware utilization without amortizing context encoding. Existing evaluation
also omits adaptive calibration, selective accuracy, high-confidence mistakes,
paraphrase consistency, and separated fan-out timing.

## Architecture candidates

Only three candidates are in scope:

1. **Scalar cross-encoder baseline.** Train the existing architecture on v1.2
   data. Expected quality improvement comes only from data and the corrected
   support contract. Fan-out cost and memory behavior remain unchanged. This is
   the lowest-complexity control.
2. **Multi-task cross-encoder.** Keep the same support head and add masked NLI,
   relevance, and assertion-strength heads. Inference cost is effectively
   unchanged because auxiliary heads are not needed by the SDK. Training adds
   small linear heads and modest complexity. This candidate tests whether the
   scalar objective was discarding useful structure.
3. **Shared-context multi-task encoder.** Encode context tokens once, encode
   assertions separately, and let each assertion summary attend over cached
   context states. It should improve large fan-out latency, but it may lose
   token-level interaction quality and cache long context states. It remains
   experimental unless it wins the complete quality/efficiency comparison.

Backbone changes are configuration experiments rather than a fourth
architecture. DeBERTa-v3-base and ModernBERT-base should be tested only after
the data and objective ablations. Pooling is explicit checkpoint metadata:
released checkpoints default to `first_token`, while ModernBERT can be tested
with its conventional `mean` pooling without changing old checkpoint meaning.

## Minimum experiments

- **Data hypothesis:** initialize the scalar cross-encoder from v1.1 and train
  on v1.2 data. Compare with v1.1 on every unchanged test set and the new
  capability development sets.
- **Objective hypothesis:** repeat with the multi-task cross-encoder using the
  same backbone, initialization, data order, seed, and optimizer settings.
  Disable auxiliary loss weights for the control.
- **Backbone hypothesis:** only if both cross-encoder experiments plateau, run
  the winning objective with one stronger backbone. Compare quality per
  parameter, millisecond, checkpoint byte, and peak VRAM.
- **Fan-out hypothesis:** train the shared-context candidate with the winning
  data/objective and compare it at 1/2/5/10/25/50/100/250/1000 assertions. A
  speed gain does not qualify it if semantic or calibration regressions are
  material.

## Data

The v1.2 preparation step keeps the v1.1 public data and adds:

- [HANS](https://github.com/tommccoy1/hans), MIT licensed, using its published
  augmentation set for training and its official evaluation set only for
  reporting. It targets high-overlap unsupported inferences and structural NLI
  shortcuts.
- SQuAD hard relevance pairs. Positives are biased toward low lexical overlap;
  negatives prefer a different passage from the same topic and reject passages
  containing the known answer text. Train, validation, and test continue to use
  disjoint SQuAD partitions.
- Deterministic v1.2 generators for lexical directionality, negation, modality,
  temporal language, numeric relations, software systems, performance, and
  unsupported conclusions. Train, validation, test, and frozen holdout use
  disjoint vocabulary and surface-form families.

ANLI is excluded because its CC BY-NC license would add a noncommercial
constraint. PAWS is reserved as a possible diagnostic because “not paraphrase”
is not a clean one-way support label.

Generated files remain under `data/`. The second frozen semantic holdout and
its hash are under `benchmarks/`; the preparation script never adds it to a
training split. The original hard challenge remains unchanged and is run only
after experiment selection.

## Evaluation and selection

`scripts/evaluate.py` reports accuracy, AUROC, NLL, Brier score, fixed-bin ECE,
adaptive ECE, high-confidence errors at 0.90/0.95/0.99, selective accuracy, and
metrics by source and capability. It writes the individual high-confidence
mistakes for review. Robustness evaluation measures paraphrase probability
deltas and diagnostic complement behavior.

Validation is partitioned into model selection, calibration fit, and
calibration-method selection. Temperature, Platt, and beta calibration are fit
only on calibration data and compared on the separate selection partition.
The chosen method is then evaluated once on test and frozen holdouts.

A candidate is selected only after comparing:

- semantic accuracy overall and by capability;
- AUROC and ranking behavior;
- NLL, Brier, ECE, adaptive ECE, and high-confidence errors;
- paraphrase consistency and template-OOD performance;
- CAPE-Mix-v1 retention;
- parameters, checkpoint size, CPU/GPU median and p95 latency, throughput, and
  peak CUDA memory;
- frozen challenge and frozen v1.2 holdout results after other decisions are
  complete.

The generic System-One harness separates boolean, choice, ordered-score, and
fan-out task types. CAPE deliberately reports ordered scoring as unsupported
until an ordinal objective and calibration method exist. External adapters can
implement the same protocol without putting credentials in the repository.
